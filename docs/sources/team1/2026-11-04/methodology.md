# Методика SunCount — исправленный расчёт YEARWISE, 04.11.2026

**Первичный солнечный источник:** два предоставленных PVGIS JSON, 2005–2023, SARAH3/ERA5; 1 кВт, кристаллический кремний, наклон 30°, юг, потери 14%, горизонт учтён. Краснодар 45.0355/38.9753, Майкоп 44.6098/40.1007. Исходные файлы находятся в `data/pvgis_raw/`. PVGIS является расчётной моделью физической генерации, не данными бытового счётчика.

**Нагрузка:** `day_absent`, `home_all_day`, `ac`, `el_heating` — 8 сценарных профилей, по 8760 часовых величин для двух городов. Помесячные объёмы взяты из ранее согласованного пакета `data/reference/monthly_load_2023.csv`. `build_profile` создаёт условный почасовой рисунок с дневными/вечерними пиками и сезонными приборами. Отдельно добавлены двухнедельные ряды пяти расчётных домохозяйств для сценарной сверки. См. `docs/household_validation.md`.

## Расчёт по годам

1. Конверсия UTC в фиксированное UTC+3; часовые метки выравниваются по месяцу, числу и часу условного невисокосного года (8760 часов), 29 февраля исключается. Для 01.01.2005 00:00–02:59 отсутствуют исходные записи после перехода в UTC+3; для трёх ночных часов подставлено 0 кВт·ч солнечной генерации.
2. Для каждого **конкретного года** и каждого часа считаем самопотребление `min(load,gen)`, сетевой импорт `max(load-gen,0)`, экспорт `max(gen-load,0)`. Дневной импорт соответствует 07–23, ночной — 23–07 (начало включительно), UTC+3.
3. Суммируем энергии по **каждому месяцу каждого года**, затем берём арифметическое среднее каждой энергетической колонки по 19 годам.
4. Годовой баланс — сумма полученных 12 месяцев. Доли `self_share` и `coverage` вычисляем **из агрегированных энергий** (без усреднения готовых процентов).
5. Усреднённый почасовой PVGIS 8760 используется **только для графика**, никогда для экономического баланса. `simulate()` возвращает контракт прежнего v1.0.

**Для сравнительного исследования:** годовое потребление `day_absent` и `home_all_day` фиксируется на 3500 кВт·ч на семью и город, рисунок потребления пропорционально масштабируется. Порог 1,5 выполняется для отношения долей, рассчитанных из средних энергий 2005–2023, во всех 6 сочетаниях города и мощности. Это не гарантирует выполнение порога в каждом году: Краснодар, 10 кВт — ниже 1,5 в 2018 и 2020 годах, минимум 1,499000839 в 2020 году; диапазон 1,499000839–1,525171454, 17 из 19 лет достигают порога. У остальных пяти сочетаний порог выполняется в каждом из 19 погодных лет. Вывод относится к сценарным нагрузкам и не подтверждён измерениями семей.

**Аудит:** полные по-годовые записи `energy_metrics_per_year.csv`, `energy_metrics_monthly_per_year.csv`, разница методов `team1_typical_year_check.csv`, автопроверки `scripts/check_team1_data.py` и `tests/` (13 тестов). Суммы и балансы проверены. Данные о генерации берутся из приложенного JSON, а не заменяются ориентиром команды 2; расхождение 1223,55 против около 1240 кВт·ч/(кВт·год) по Краснодару требует сверки настроек/источников.

**Интеграция:** оригинальный `MonthlyMetrics` второй команды нужно получить и проверить перед финальным объединением, формат v1.0 не расширен. Дополнительный портрет `pump_farm` не создавался. Условный год нагрузки одинаков при сопоставлении разных погодных лет, независимо от фактического распределения дней недели в историческом году; это ограничение дизайна моделирования.

**Изменение профиля:** см. `docs/profile_changes_2026-11-04.md`. Эта версия не меняет часовые веса от 02.11.2026. Все CSV имеют BOM (`utf-8-sig`).

**Сверка домохозяйств:** пять расчётных семей Краснодара и Майкопа, по 14 суток, 1680 часов. MAE/MAPE рассчитаны по часам и суткам на отложенной неделе. Генератор, параметры, происхождение и ограничения: `docs/household_validation.md`. `pump_farm` в текущую сдачу не включается.
