# SunCount — итоговый расчёт команды №1 по отдельным годам PVGIS

**Дата:** 03.11.2026  
**Версия:** YEARWISE-2005–2023 / v1.0  
**Статус:** исправлены энергетические показатели и API в соответствии с замечаниями команды №2. Проверены 13 автоматических тестов. Остались внешние этапы: сверка оригинального класса `MonthlyMetrics` команды №2 и валидация профилей по измерениям домохозяйств.

## 1. Исправление методической ошибки

Предыдущая версия сначала усредняла по годам выработку каждого часа, а затем использовала `min(load, average_pv)`. Это сглаживало облачность и завышало самопотребление.

**Исправленный алгоритм:**

1. Для каждого города берётся почасовая PVGIS-SARAH3 серия 2005–2023: по 19 календарных лет.
2. Каждая серия переводится из UTC в UTC+3, исключается 29 февраля, выравнивается на 8760 почасовых значений. Отсутствующие три ночных часа 01.01.2005 заполнены нулевой генерацией.
3. Одна и та же условная почасовая нагрузка профиля (8760 значений) сравнивается **отдельно с каждым из 19 лет**. Она намеренно фиксирована, чтобы выделить влияние межгодовой погоды; это не реальные показания счётчика за 19 лет.
4. Для каждого часа вычисляются `self=min(load,gen)`, `import=max(load-gen,0)`, `export=max(gen-load,0)` и разбиение импорта на день и ночь.
5. Энергии суммируются по месяцам в каждом году, после чего **усредняются месячные энергии** за 19 лет; годовые показатели — сумма средних месяцев.
6. `self_share = 100 × mean(self_kwh)/mean(gen_kwh)`, `coverage = 100 × mean(self_kwh)/mean(load_kwh)`; проценты разных лет **не усредняются напрямую**.
7. Только для графика среднего дня возвращается усреднённый почасовой ряд солнечной генерации. API `simulate(load_8760, pv_kw, city, tilt=30, azimuth=180)` сохранён.

Прежний способ завышал `self_share` на **0,72–6,36 процентного пункта** по всем 24 сочетаниям. Полная сверка — `results/team1_typical_year_check.csv`.

## 2. Источники и параметры

- Полученный пользователем архив двух PVGIS JSON: `data/pvgis_raw/pvgis_2005_2023_original_upload.zip`. Каждый содержит **166 536** исходных часовых значений за 2005–2023 годы (включая високосные дни). Проверены параметры, полнота и внутренняя непротиворечивость.
- **Краснодар:** 45.0355, 38.9753. **Майкоп:** 44.6098, 40.1007.
- Источник: **PVGIS 5.3 / SARAH3 + ERA5**, c-Si, 1 кВт, угол 30°, ориентация на юг (PVGIS `aspect=0`, API `azimuth=180`), потери 14%, горизонт включён, крепление free-standing.
- Мощности 3, 5, 10 кВт рассчитаны линейным масштабированием мощности модели 1 кВт.
- Тарифные периоды: день 07:00–22:59 и ночь 23:00–06:59, UTC+3, без аккумулятора.
- Средняя PVGIS-генерация 1 кВт в год: Краснодар **1223,55 кВт·ч**, Майкоп **1210,43 кВт·ч**.
- Отличие от предварительного ориентира команды №2 (Краснодар ~1240 кВт·ч/кВт·год) по-прежнему требует сверки одинаковых параметров и исходных файлов. Показания в поставке не заменены ориентиром.

## 4. Гипотеза при одинаковом годовом потреблении

Годовое потребление `day_absent` и `home_all_day` отдельно нормировано до **3500 кВт·ч в каждом городе**. Сравнивается `self_share`, то есть доля выработки, непосредственно использованная в доме. Каждый вариант рассчитывается по 19 годам до усреднения. Результат:

| Город | Мощность | Self-share: никого дома | Self-share: кто-то дома | Отношение | ≥ 1,5 |
|---|---:|---:|---:|---:|:---:|
| Краснодар | 3 кВт | 24,57% | 38,58% | **1.5704×** | Да |
| Краснодар | 5 кВт | 16,44% | 25,46% | **1.5492×** | Да |
| Краснодар | 10 кВт | 9,18% | 13,87% | **1.5106×** | Да |
| Майкоп | 3 кВт | 24,51% | 38,59% | **1.5747×** | Да |
| Майкоп | 5 кВт | 16,36% | 25,49% | **1.5578×** | Да |
| Майкоп | 10 кВт | 9,15% | 13,92% | **1.5204×** | Да |

**Вывод:** отношение составило **1.5106–1.5747×**. При выбранных сценарных нагрузках и PVGIS 2005–2023 гипотеза «не менее 1,5» **выполняется для всех шести сочетаний**. Результат относится только к принятой модели потребления; без измерений семей он не является доказательством закономерности для реальных домохозяйств.

## 5. Проверки качества

- Проведено **13 автоматических тестов**, все прошли.
- Проверены почасовые тождества `load=self+import` и `gen=self+export`; сумма дневного и ночного импорта равна полному импорту.
- Проверено совпадение средних по 19 годам с годовыми результатами и годовых результатов с суммой 12 месяцев.
- `simulate` возвращает те же сигнатуры и 12 помесячных объектов `MonthlyMetrics`; почасовые массивы для визуализации длиной 8760.
- Принятые отсутствующие три часа в начале 2005 года относятся к ночи, и для них нулевая генерация согласована с методом.

## 6. Ограничения и дальнейшее согласование

1. **Не представлены 3–5 семей с фактическими наблюдениями**, поэтому бытовые нагрузки не являются проверенными измерениями. Нужна валидация модели по данным 1–2 недель для каждой семьи с согласия участников.
2. Оригиналы `docs/exchange_format.md` и `src/econ/exchange.py` команды №2 не представлены. В составе пакета — восстановленный формат v1.0 и совместимый локальный класс; нужна сверка при объединении репозиториев.
3. Для каждого исторического солнечного года используется один сценарный невисокосный календарь нагрузки 2023; календарная структура будней и выходных не привязана к фактическим датам 2005–2023. Это контролируемое модельное допущение.
4. В исходных PVGIS-JSON есть несовпадение с ранее озвученным ориентиром команды №2 по генерации. Для сверки необходим их исходный запрос/JSON. На годовом соотношении это может влиять на результаты.
5. СЭС масштабирована линейно от 1 кВт, без накопителя; экономические вопросы (тарифы, выкуп, деградация, стоимость СЭС, окупаемость) находятся у команды №2.
