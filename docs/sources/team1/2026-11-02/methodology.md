# Методика и ограничения — SunCount, команда №1

## 1. Что является исходными данными

1. **PVGIS 5.3 / PVGIS-SARAH3** — физически рассчитанная выработка СЭС, а не счётчик электрической станции. SARAH3 даёт солнечную радиацию 2005–2023; климатические параметры подбирает модель PVGIS, в том числе из ERA5. В проекте применяются 1 кВт, `loss=14`, `angle=30`, PVGIS `aspect=0` (на юг), горизонт учитывается, кремниевые модули; PV мощности 3/5/10 масштабируются от 1 кВт. Города — Краснодар 45.0355, 38.9753; Майкоп 44.6098, 40.1007.
2. **Месячные нагрузки портретов** — из ранее переданного по SunCount CSV за 2023 год, округление до 0,001 кВт·ч. **Они не являются наблюдениями 3–5 семей.**
3. **Часовой рисунок нагрузки** — формализованный набор весов, учитывает присутствие, завтраки, ужины, выходные и условные приборы. Это результат модели, а не измерение прибора в доме.
4. **Полученная солнечная база** — пользовательский оригинальный ZIP с двумя PVGIS JSON 2005–2023. Все месяцы и сутки выработки извлечены из этих файлов (166 536 записей на город). Их SHA256 и валидация параметров задокументированы. Старые демонстрационные временные данные заменены реальными расчётными рядами PVGIS.

## 2. Как получают настоящую многолетнюю серию

В данной поставке считывается приложенный архив через `python -m scripts.import_uploaded_pvgis`; прямой вызов сервера не нужен. При необходимости обновления вызывается `PVGIS 5.3/seriescalc` с `raddatabase=PVGIS-SARAH3`, `startyear=2005`, `endyear=2023`, `pvcalculation=1`, `peakpower=1`, `loss=14`, `angle=30`, `aspect=0`, `usehorizon=1`, `mountingplace=free`. Сохраняется оригинальный JSON и его SHA256. Время PVGIS преобразуется в местное `UTC+3`; для **каждого часа невисокосной календарной маски** берется среднее выработки за соответствующие месяц, день и час из 2005–2023; 29 февраля исключается. Такой профиль содержит ровно 8760 почасовых значений и сохраняет внутри-месячную структуру генерации, а не просто месячные итоги.

Важное отличие: это «средний почасовой типовой год», не стохастический 25-летний прогноз и не наблюдённые 8760 часов конкретного года. За календарные границы локального времени часть ночных часов опирается на 18 вместо 19 лет; это не влияет существенно на PV, поскольку ночью генерация нулевая. Промежутки времени от PVGIS при считывании округляются до начала соответствующего часа.

## 3. Почасовое потребление

В портретах представлены:

- `day_absent` — утренняя и вечерняя активность; в рабочие часы 09:00–17:00 потребление меньше.
- `home_all_day` — базовая дневная активность, более равномерное распределение.
- `ac` — первый профиль с дополнительным дневным охлаждением, усиленным в мае–сентябре.
- `el_heating` — первый профиль с условным круглосуточным отоплением, усиленным зимой и в межсезонье.

Условные группы приборов (не являются проверенной инвентаризацией конкретных семей): фоновая холодильная и сетевая нагрузка, освещение, готовка, электроотопление, кондиционер, насос. `appliances={'ac','el_heating','pump','el_stove'}` изменяет **распределение во времени** согласно сезонности и почасовому весу, но не заданный `monthly_kwh`; это предотвращает двойной подсчёт приборов, если их расход уже включён в месячный счёт.

## 4. Самопотребление и гипотеза

Почасовое самопотребление: `min(load, generation)`, покупка: `max(load-generation, 0)`, выдача: `max(generation-load, 0)`. Доля самопотребления `self_share = self / gen` (%) — именно она в гипотезе команды 1; `coverage = self / load` (%) измеряет другую величину. Нагрузка `day_absent` и `home_all_day` **отдельно масштабируется до 3500 кВт·ч/год** при сохранении всех относительных почасовых и месячных весов. Сравнение проводится отдельно для каждой мощности и города.

При одинаковом годовом расходе и одинаковой выработке на сравниваемые портреты **отношение `self_share` и отношение `coverage` неизбежно совпадают** алгебраически. Поэтому отдельные отношения самопотребления и покрытия 1,59–1,63 и 1,36–1,39, которые сообщала команда 2, были получены при неравных расходах.

Показатели в `results/hypothesis_equal_consumption.csv` пересчитаны по многолетнему PVGIS. Выводы относятся к сценарным, не эмпирически валидированным нагрузкам, поэтому остаются модельными. Нельзя утверждать подтверждение гипотезы для всех мощностей при наличии хотя бы одного отношения меньше 1,5.

## 5. Источники / контроль

- Официальный JRC, API PVGIS 5.3: https://joint-research-centre.ec.europa.eu/photovoltaic-geographical-information-system-pvgis/using-pvgis-5/api-non-interactive-service_en
- Обзор PVGIS 5.3 и база SARAH3 2005–2023: https://joint-research-centre.ec.europa.eu/photovoltaic-geographical-information-system-pvgis/using-pvgis-5_en
- Базовые месячные нагрузки — из предыдущего пакета SunCount (`data/reference/`). Оригинальные PVGIS JSON находятся в `data/pvgis_raw/pvgis_2005_2023_original_upload.zip`. Контрольные числа команды №2 для трёх месяцев Краснодара документированы в `results/comparison_team2_reference.csv`, но не использованы для замены фактических значений JSON.
- Исходные измерения реальных семей **отсутствуют**. Для научной валидации их нужно запросить отдельно с согласия семей, сравнить дневные доли/недели и зафиксировать метрики ошибки (MAE/MAPE).

## 6. Ограничения внедрения

Файл `docs/exchange_format.md` команды 2 не приложен; поля восстановлены по предыдущему проверенному CSV v1.0. В проекте есть совместимый `src/econ/exchange.py`, но его следует заменить оригиналом второй команды при интеграции. Версия API PVGIS, восприятие часовых меток (конец/начало интервала) и форма почасовой генерации должны быть уточнены с их моделью; контроль трех месяцев и годовых сумм позволит выявить расхождения.

## 7. Статус результата после получения 19-летней серии

ПВ-часть рассчитана по пользовательским многолетним PVGIS JSON. В отличие от DEMO-базы из прежнего пакета, результаты теперь в статусе `VERIFIED` по **структуре, полноте, внутренней непротиворечивости и параметрам предоставленных данных**. Это не означает независимую цифровую аттестацию источника, верификацию бытового потребления реальными счётчиками или проверку интеграции с оригинальным классом команды 2. Наблюдения 3–5 семей остаются не предоставленными.
