## 1. Зачем эта роль

Калькулятор — **итоговый продукт проекта** по ТЗ курса. Первый критерий приёмки: «Калькулятор выдаёт рекомендуемую мощность, долю самопотребления и срок окупаемости **для любого портрета и тарифа**». По ТЗ за интерфейс отвечает команда 2, а команда 1 подключает свой модуль.

**Требования ТЗ курса к калькулятору (дословно):**
1. «Веб-интерфейс на Python (например, Streamlit)».
2. «Входные данные: выбор готового портрета или ввод своих данных (месячное потребление, когда в доме кто-то есть, основные приборы), населённый пункт, тариф».
3. «Результат: рекомендуемая мощность СЭС из вариантов 3, 5 и 10 кВт (с наименьшим сроком окупаемости), доля самопотребления, годовой эффект в рублях и срок окупаемости».
4. «График суточного профиля потребления на фоне выработки СЭС для летнего и зимнего дня».
5. «Краткая подсказка пользователю, как сократить срок окупаемости, например перенести стирку и нагрев воды на дневные часы».

**Твои итоговые результаты:**


## 4. Архитектура приложения

```
app/
├── streamlit_app.py   точка входа: страница, ввод, вывод
├── calc.py            расчёт: собирает энергетические данные и вызывает модель (без Streamlit внутри)
├── charts.py          графики (matplotlib)
└── texts.py           тексты подсказок и пояснений
```

**Правила:**
1. **Расчёт отделён от интерфейса.** В `calc.py` нет `import streamlit`; его можно вызвать из теста или консоли. Р5 будет проверять именно его.
2. **Числа — только из модели.** До 22.11 — через функции `src/econ/model.py`, как в типовом вызове (раздел 7.4 мастер-ТЗ). После — через `src/econ/api.py` (`evaluate`, `recommend`) от Р1. Никаких своих формул окупаемости в приложении.
3. **Импорт модели:**
   ```python
   import sys
   from pathlib import Path
   ROOT = Path(__file__).resolve().parents[1]
   sys.path.insert(0, str(ROOT))
   from src.econ.inputs import TariffPlan
   ```
4. **Загрузку CSV** обернуть в `@st.cache_data`.
5. **Запуск** из корня репозитория: `streamlit run app/streamlit_app.py`, откроется `http://localhost:8501`.
6. **Шрифт графиков:** не указывать только Arial — на сервере без Windows его нет. Писать `plt.rcParams["font.family"] = ["Arial", "DejaVu Sans"]`.

### T4.2. Ввод данных по ТЗ (до 30.11)

**Режим 1 — «Готовый портрет»:**
- выбор из 5 портретов (коды из `docs/exchange_format.md`): `day_absent` «Семья днём на работе / учёбе», `home_all_day` «Кто-то дома весь день», `ac` «Дом с кондиционером», `el_heating` «Электроотопление / электробойлер», `pump_farm` «Насос и подсобное хозяйство»;
- данные портрета — из файлов команды 1 (`data/energy_metrics_monthly.csv`, через `read_csv(path, MonthlyMetrics)`), отфильтрованные по портрету, городу и мощности;
- **пока файлов нет:** режим виден, но вместо расчёта показывается `st.info("Портреты появятся после передачи данных командой 1 (до 04.12). Пока используйте режим «Свои данные».")`.

**Режим 2 — «Свои данные»:**
- потребление: переключатель «одно среднее значение» (кВт·ч в месяц, `st.number_input`, 50…5000, по умолчанию 500) / «по месяцам» (12 полей в `st.expander`);
- «Когда в доме кто-то есть»: «днём никого (работа, учёба)» → `presence="day_absent"`, «кто-то дома весь день» → `presence="home_all_day"`;
- «Основные приборы» (`st.multiselect`): кондиционер → `"ac"`, электроотопление или бойлер → `"el_heating"`, скважинный насос → `"pump"`, электроплита → `"el_stove"`;
- **до подключения модуля команды 1:** профиль строит `make_stub_monthly`, а долю самопотребления задаёт временный ползунок 20–80 %. Рядом пометка «условный расчёт до подключения модуля команды 1».

**Общие поля:** город, тариф. Дополнительно: «У меня есть своя цена станции» (`st.checkbox`) → поля цены для 3, 5 и 10 кВт; используются вместо `capex_base_rub` — в `api.evaluate` параметр `capex_rub`.

**Проверка ввода:** отрицательные и нулевые значения не принимать (`min_value` у `number_input`); если потребление по месяцам — все 12 полей обязательны.

### T4.3. Вывод результата (до 30.11)

**Верх страницы** — 4 карточки `st.metric`:

| Карточка | Значение | Пояснение (`help=`) |
|---|---|---|
| Рекомендуемая мощность | «5 кВт» | «Вариант из 3, 5 и 10 кВт с наименьшим простым сроком окупаемости» |
| Срок окупаемости | «7,7 года» | «Стоимость станции / годовой эффект первого года» |
| Годовой эффект | «51 900 ₽» | «Экономия на счёте за электричество + доход от продажи излишков» |
| Доля самопотребления | «40 %» | «Какая часть выработки СЭС расходуется в доме, а не уходит в сеть» |

**Ниже:**
- таблица «Сравнение мощностей»: мощность, стоимость станции, годовой эффект, из него доход от излишков (₽ и %), простой срок, срок при цене станции от минимальной до максимальной (`payback_low…payback_high`), дисконтированный срок;
- пояснение одной строкой: «Дисконтированный срок учитывает рост тарифов, износ панелей, замену инвертора и налог после 2029 г.»;
- раскрывающийся блок «Как считается» со ссылкой на методику в репозитории.

**Правила вывода чисел:**
- рубли — с пробелами между разрядами: «51 903 ₽»;
- годы — один знак после запятой, с запятой: «7,7»;
- проценты — целые;
- `inf` → «не окупается за 25 лет»;
- функции форматирования положить в `app/texts.py`.

### T4.4. График «потребление на фоне выработки» для летнего и зимнего дня (до 07.12)

**Данные:** почасовые потребление и выработка из `simulate()` команды 1 (`docs/api_team1.md`, задача Р1 T1.3).

**Что рисовать:**
- два графика рядом: «Летний день (средние сутки июля)» и «Зимний день (средние сутки января)»;
- по оси X — часы 0–23 (местное время);
- линии: потребление дома и выработка СЭС, кВт·ч за час;
- закрашенная область — самопотребление (минимум из двух кривых);
- вертикальные линии 7:00 и 23:00 — границы зон день/ночь.

«Средние сутки месяца» — среднее по всем дням месяца для каждого часа. Это определение написать в подписи под графиком.

**До подключения модуля команды 1:** вместо графиков — `st.info("График появится после подключения модуля команды 1")`. Не рисовать выдуманные кривые.

### T4.5. Подсказки пользователю (до 07.12)

Подсказки **считаются** моделью, а не пишутся «на глаз». Логика в `app/calc.py`, тексты — в `app/texts.py`. Формулировки согласовать с Р3.

| Условие | Как посчитать | Текст |
|---|---|---|
| Выбран одноставочный тариф | Пересчитать с тарифом день/ночь той же местности (город → `city_zones`, село → `rural_zones`). `gain` = срок(одноставочный) − срок(день/ночь) | «Переход на тариф день/ночь сократит срок окупаемости на {gain} года» (только если `gain` ≥ 0,5) |
| Доля самопотребления < 50 % | До подключения команды 1: пересчитать с долей +10 п. п. После: сдвинуть 2 кВт·ч в сутки потребления с вечерних часов (19–22) на дневные (11–14) в почасовом профиле и заново вызвать `simulate` | «Перенесите стирку и нагрев воды на дневные часы: доля самопотребления вырастет до {X} %, срок сократится на {Y} года» |
| Рекомендованная мощность меньше 10 кВт | Сравнить сроки трёх мощностей | «Станция {N} кВт для вашего потребления избыточна: больше энергии уходит в сеть по цене выкупа» — для каждой мощности больше рекомендованной, у которой срок хуже минимального на 1 год и более |
| Срок `inf` для всех мощностей | — | «При таком потреблении станция не окупается за 25 лет» |

Показывать не больше 3 подсказок, сначала с самым большим выигрышем.
