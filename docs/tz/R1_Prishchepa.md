### T1.4. Единая точка входа `src/econ/api.py` (до 22.11)

**Зачем:**
- Калькулятор (Р4), аналитика (Р3) и тесты (Р5) должны вызывать модель одинаково.
- ТЗ курса требует, чтобы на вход модуля можно было подать **тариф и цену выкупа**. Сейчас `annual_effect_monthly` берёт цену выкупа сама из `inputs.buyback_monthly`, поэтому её нужно сделать переопределяемой.

**Спецификация:**

```python
# src/econ/api.py
from dataclasses import dataclass

@dataclass
class Result:
    pv_kw: float
    capex_rub: float          # использованные капзатраты
    self_share: float         # %, из энергетических данных
    coverage: float           # %
    self_rub: float           # экономия на счёте за год (первый год, цены 01.10.2026)
    export_rub: float         # доход от излишков за год
    effect_rub: float         # годовой эффект
    export_share: float       # % излишков в эффекте (гипотеза 2)
    simple_payback: float     # лет; inf — не окупается
    disc_payback: float       # лет; inf — не окупается за срок службы
    npv_rub: float
    payback_low: float        # простой срок при capex_low (data/capex_estimate.csv)
    payback_high: float       # простой срок при capex_high

def evaluate(months: list[MonthlyMetrics], plan: TariffPlan, pv_kw: float,
             capex_level: str = "base",            # "low" | "base" | "high" — колонка capex_estimate.csv
             capex_rub: float | None = None,       # своя цена пользователя — приоритетнее capex_level
             buyback_rub_kwh: float | None = None, # своя цена выкупа: одна на все месяцы
             scenario: Scenario | None = None) -> Result: ...

def recommend(months_by_kw: dict[int, list[MonthlyMetrics]], plan: TariffPlan,
              **kwargs) -> tuple[int, dict[int, Result]]:
    """Мощность с наименьшим простым сроком окупаемости (по ТЗ) + результаты по всем мощностям."""
```

**Правила реализации:**
1. **Внутри — только существующие функции** `model.py`: `annual_effect_monthly`, `cash_flows`, `discounted_payback`, `npv`, `simple_payback`.
2. **Для `buyback_rub_kwh`** добавить в `annual_effect_monthly` необязательный параметр `buyback: dict[int, float] | float | None = None`. При `None` — как сейчас; при числе — одна цена на все месяцы. Поведение по умолчанию не меняется, тесты Р5 должны проходить.
3. **`Scenario`** по умолчанию — `Scenario(inverter_cost_rub=<inverter_rub из capex_estimate.csv для pv_kw>)`, как в `scripts/stub_payback.py`.
4. **`capex_estimate.csv`** читать один раз (`functools.lru_cache`), как сделано в `inputs.py`.
5. **`recommend`:**
   - если сроки равны (до 0,05 года), выбирать **меньшую** мощность: она дешевле;
   - если все сроки `inf`, вернуть мощность с наибольшим `effect_rub` и пометку в результате;
   - выбор по **простому** сроку — так в ТЗ. Если наставник скажет иначе (вопрос 8 в мастер-ТЗ), поменять в одном месте.
6. **Формулу ТЗ** оставить доступной: `annual_effect(m, tariff, buyback)` уже есть. В api добавить тонкую обёртку `evaluate_tz(metrics: EnergyMetrics, tariff_rub: float, buyback_rub_kwh: float, capex_rub: float) -> Result`. Это дословная реализация требования ТЗ «на входе показатели раздела 4, тариф и цена выкупа».

**Проверка:** результат `evaluate(make_stub_monthly("s", 5, 6000, 40), TariffPlan("Город, день/ночь", "base", "two_zone", ("base",)), 5)` должен совпасть с `scripts/stub_payback.py` для той же точки: эффект ≈ 51 903 ₽, простой срок 7,7, дисконтированный 9,2.

*Готово, когда:* файл в `main`, тесты Р5 на api проходят, Р3 и Р4 перешли на api.
