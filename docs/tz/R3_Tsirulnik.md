## 4. Задачи

### T3.1. Анализ чувствительности — «торнадо» (прототип до 30.11, финал до 12.12)

**Базовый случай:**
- СЭС 5 кВт, Краснодар, потребление 6000 кВт·ч/год;
- доля самопотребления 40 % (на условных данных — `make_stub_monthly("base", 5, 6000, 40, "krasnodar")`, на реальных — портрет команды 1);
- капзатраты — база из `data/capex_estimate.csv`;
- `Scenario(inverter_cost_rub=<inverter_rub для 5 кВт>)`;
- считать для **каждого из 4 тарифов** (`TariffPlan` из раздела 7.2 мастер-ТЗ).

**Метод:** меняем **по одному** параметру — сначала на нижнее, потом на верхнее значение, остальные — базовые. Записываем простой и дисконтированный срок окупаемости. «Размах» = |срок при верхнем − срок при нижнем|. Чем больше размах, тем сильнее параметр влияет.

**Параметры, значения и как их задать в коде:**

| № | Параметр | Низ | Верх | Как задать | Откуда диапазон |
|---|---|---|---|---|---|
| 1 | Тариф | −20 % | +20 % | умножить `self_rub` на 0,8 / 1,2 | обоснованный размах для сравнения факторов |
| 2 | Доля самопотребления | 20 % | 50 % (5 кВт) | новые `months = make_stub_monthly(..., 20 / 50, ...)` | ТЗ: 20–80 %; при 6000 кВт·ч/год и 5 кВт выше 50 % недостижимо (см. ниже) |
| 3 | Цена выкупа | мин. по месяцам | макс. по месяцам | умножить `export_rub` на коэффициент (ниже) | `data/buyback_by_category.csv` |
| 3а | Цена выкупа, сценарий «ТНС платит вдвое меньше» | ×0,5 | — | умножить `export_rub` на 0,5 | на случай, если ТНС не подтвердит расчёт |
| 4 | Капзатраты | `capex_low_rub` | `capex_high_rub` | другое значение `capex` | `data/capex_estimate.csv` |
| 5 | Ставка дисконтирования | −3 п. п. | +3 п. п. | `discount_rate={y: r ± 0.03 …}`, `long_run_discount=0.08 ± 0.03` | прогноз ЦБ, `params.py` |
| 6 | Рост тарифа | 4 %/год | прогноз МЭР | `tariff_growth={}` (тогда весь срок — `long_run_growth` = 4 %) | `params.py` |
| 7 | Срок службы | 25 | 30 лет | `lifetime=30` | гарантия панелей 30 лет |
| 8 | Деградация | 0,4 %/год | 0,6 %/год | `degradation=0.006` | гарантия производителя / исследование Sandia |
| 9 | НДФЛ | с 2029 г. | льготу продлят | `ndfl_free_until=2100` | ст. 217 НК РФ |
| 10 | Обслуживание | 0 | 1 % капзатрат в год | `opex_rub=0.01 * capex` | допущение, `assumptions.md` |

Параметры 5–10 влияют только на **дисконтированный** срок: простой срок — это капзатраты / эффект первого года. В таблице для них простой срок не меняется, это нормально, так и написать.

**Коэффициенты для цены выкупа (п. 3)** — из `data/buyback_by_category.csv`, май–сентябрь 2026:
- одноставочный: низ = 4,064 / 4,443 = 0,915; верх = 4,671 / 4,443 = 1,051;
- день/ночь: низ = 7,303 / 7,522 = 0,971; верх = 7,897 / 7,522 = 1,050.

Считать коэффициенты кодом из CSV, а не вписывать руками: данные будут обновляться (T2.5).

**Почему у 5 кВт не 80 %:** на условных данных дом потребляет 500 кВт·ч в месяц, из них днём 350. Летом СЭС 5 кВт вырабатывает около 700 кВт·ч в месяц, и съесть больше половины дом не может. `scripts/stub_payback.py` такие точки отбрасывает. Для полной оси 20–80 % сделать дополнительный прогон на 3 кВт, а на реальных данных доля будет своя у каждого портрета.

**Как масштабировать результат** (`Economics` — из `src/econ/model.py`):

```python
from dataclasses import replace
from src.econ.model import Economics, Scenario, annual_effect_monthly, cash_flows, simple_payback, discounted_payback

def scaled(e: Economics, k_self: float = 1.0, k_export: float = 1.0) -> Economics:
    s, x = e.self_rub * k_self, e.export_rub * k_export
    return Economics(s, x, s + x, 100 * x / (s + x))

def paybacks(e: Economics, capex: float, sc: Scenario) -> tuple[float, float]:
    return simple_payback(capex, e.effect_rub), discounted_payback(capex, cash_flows(e, capex, sc), sc)

# пример: ставка дисконтирования +3 п. п.
sc_hi = replace(sc, discount_rate={y: r + 0.03 for y, r in sc.discount_rate.items()},
                long_run_discount=sc.long_run_discount + 0.03)
```

После готовности `src/econ/api.py` (Р1, 22.11) цену выкупа менять через параметр `buyback_rub_kwh`, а не масштабированием.

### T3.2. Влияние тарифа по зонам суток (до 30.11, на реальных данных — до 12.12)

**Зачем:** отдельное требование ТЗ. Наш предварительный вывод: день/ночь сокращает простой срок для 5 кВт на 2,5–4,1 года в городе и на 3,4–4,8 года на селе. Нужно показать это по всем портретам и мощностям и объяснить, **откуда** выигрыш.

**Метод:** для каждой точки (портрет или условная доля, мощность, город) посчитать пары «одноставочный → день/ночь» — отдельно для города (`base`) и для села (`reduced`):
- `gain_years` = простой срок (одноставочный) − простой срок (день/ночь);
- разложение выигрыша в рублях эффекта:
  - `d_self_rub` = self_rub(день/ночь) − self_rub(одноставочный) — дорогая дневная энергия;
  - `d_export_rub` = export_rub(день/ночь) − export_rub(одноставочный) — более высокая цена выкупа дневной зоны;
- то же для дисконтированного срока.

**Формат `results/zones_effect.csv`:**
`profile, city, pv_kw, area (город/село), payback_single, payback_zones, gain_years, disc_single, disc_zones, gain_disc_years, d_self_rub, d_export_rub`

**График:** столбцы `gain_years` по портретам, цвета — город/село; второй график — разложение выигрыша (`d_self_rub` и `d_export_rub` стопкой).

**Важно для вывода:** выигрыш тарифа день/ночь в модели немного **завышен**. Модель считает всё самопотребление дневным, а летом панели работают с 5–6 утра, то есть частично в ночной зоне (`docs/assumptions.md`, ограничения). Это нужно упомянуть в выводе.

### T3.4. Проверка гипотезы 2 (до 14.12)

Гипотеза состоит из двух частей, проверять каждую отдельно.

**Часть А — «срок окупаемости определяется прежде всего тарифом и долей самопотребления».**
- Критерий: в торнадо (T3.1, финал) по **простому** сроку два самых влиятельных фактора — тариф и доля самопотребления, хотя бы для 3 из 4 тарифов.
- Если на первом-втором месте капзатраты или цена выкупа, часть А не подтверждается. Назвать, какой фактор сильнее.

**Часть Б — «доход от излишков ≤ 20 % годового эффекта».**
- Метрика: `export_share` из `results/real_payback.csv` для рекомендуемой мощности.
- Подтверждается — если ≤ 20 % у всех портретов и тарифов; частично — если у части (назвать, у каких); не подтверждается — если почти везде > 20 %.
- По предварительным данным часть Б **не подтверждается**: 12–83 % (`results/stub_payback.csv`). На реальных данных — проверить.
